## Soundness

Every query was typed by sqlsure, then executed by real Postgres through the real `pg` driver — on an empty database and on randomly seeded ones (NULL wherever allowed, JSON `null`, arrays holding NULL, parents without children) — and every returned value was checked against the claimed type.

- 38,113 values in 15,279 rows, from 588 queries over 292 schemas
- Real Postgres' own `PREPARE` must report the same column types as sqlsure for every query
- Violations: **0**

## Precision

Hand-labeled ground truth in `evals/suites/*/expect.json`: 138 of 138 truly non-null columns are typed non-null (100.0%). No misses: every column labeled non-null is typed non-null.


## Breadth

Corpus: [sqlc-dev/sqlc internal/endtoend/testdata](https://github.com/sqlc-dev/sqlc/tree/3ad8b20fb02b5bea81591b673da0758b8685d951/internal/endtoend/testdata) at `3ad8b20`, PostgreSQL cases only, deduplicated (317 duplicates), excluding 39 cases sqlc itself expects to fail.

- 599 queries; 292 translated from sqlc syntax (`sqlc.arg(x)`, `@x`, `$1` → `:x`)
- Not translatable: sqlc.slice / sqlc.embed macros (22), sqlc mode :copyfrom (7), sqlc mode :execlastid (1)
- Real Postgres rejects 20 (excluded)
- Real Postgres accepts 548; sqlsure types **548** (100.0%)
- Accepted by Postgres but not typed: 0
- Stopped by sqlsure's own checks before reaching Postgres, so outside the counts above: 1

  - `datatype/pgx/v4` Test: parse: One statement per query. Split this into separate `-- name:` blocks.
